# Changelog — orca

- 2026-09-05 — v1.0.0: a shell could not tell which layer of an Orca connection had failed, so a registration fault read as a network fault and a dead remote runtime read as a transport fault → seeds `SKILL.md` with a four-layer verify-and-repair contract (CLI presence, repo registration, remote-runtime liveness, SSH transport), a surface-to-layer map, a symptom index, and one `## Anti-patterns` registry. Admission evidence: the bundled upstream `orca-cli` guide carries the command inventory but no failure-mode diagnosis — a scan found zero occurrences of `selector_not_found`, `remote_runtime_unavailable`, `RemoteCommand`, `ControlPersist`, or crash-handler false positives, and its only ssh mention warns that forwarded invocations break skill-sharing discovery — so this package owns the repair layer and hands usage back to that guide. Boundary: `tailscale` keeps tailnet-layer reachability and disclaims generic ssh configuration problems, so the `RemoteCommand` and `ControlPersist` traps land here; `browser` keeps live-browser backends; `git` keeps plain git worktrees against Orca-managed ones. Named as a plain noun per contract §2, governing a platform surface rather than an action, matching the `tailscale` and `git` precedents. Corpus: `tests/orca/evals/evals.json` covers an unregistered sibling checkout, a remote host verdict, both ssh transport traps, and a cannot-succeed case where process listings contradict `orca status`; `tests/orca/evals/triggers.json` pairs 8 should-trigger prompts with 8 near-misses drawn from `tailscale`, `git`, `browser`, `debug`, `defuddle`, and `vmware`.
- 2026-09-13 — v1.1.0: repeated grouping, identity, and cleanup corrections exposed avoidable operator load → adds [low-clutter operations](references/operations.md), bounds non-interactive verification, preserves four-layer diagnosis, and expands scenario and routing coverage; verified_against: orca@1.4.200, git@2.50.1, openssh@10.3p1 (capability/configuration probes and operator-session evidence, not a new destructive replay). Provenance: operator-supplied Orca operating conversation, generalized without private transcript, account identifiers, or host paths; [official worktree model](https://www.onorca.dev/docs/model/worktrees), [Git branch semantics](https://git-scm.com/docs/git-branch), and [OpenSSH options](https://man.openbsd.org/ssh_config).
